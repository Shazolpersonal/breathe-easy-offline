## 2024-06-25 - Prevent Accidental Deletion with AlertDialog & Enhance ARIA on Icon-Only Buttons
**Learning:** Icon-only buttons mapping to destructive actions (like delete) on cards/lists frequently lack `aria-label` tags, causing poor screen reader experiences. Simultaneously, the lack of delete confirmations leads to inadvertent data loss.
**Action:** When auditing or building user lists/cards with icon actions, ensure all buttons are wrapped in tooltips that provide explicit `aria-label`s. Always safeguard destructive actions using an `AlertDialog` (or similar confirmation patterns) linked to an intermediate state variable (e.g., `deleteTarget`), confirming user intent before executing the deletion logic.

## 2024-05-18 - TooltipProvider Scope Constraints
**Learning:** While \`App.tsx\` provides a global \`TooltipProvider\`, when adding new Tooltip components to deep dynamic routes like \`Session.tsx\` (especially inside floating overlays or portals), it is safer and often necessary to wrap local \`Tooltip\` clusters in their own \`TooltipProvider\` to ensure context is available and layout shift is minimal. Using translation keys for \`aria-label\` alongside the visual tooltip ensures equal access for screen reader users and sighted users relying on hover states.
**Action:** When converting multiple inline icon buttons to Tooltips in complex floating/absolute positioned containers, wrap the group in a localized \`TooltipProvider\` to guarantee robust rendering.
