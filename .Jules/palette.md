## 2024-06-25 - Prevent Accidental Deletion with AlertDialog & Enhance ARIA on Icon-Only Buttons
**Learning:** Icon-only buttons mapping to destructive actions (like delete) on cards/lists frequently lack `aria-label` tags, causing poor screen reader experiences. Simultaneously, the lack of delete confirmations leads to inadvertent data loss.
**Action:** When auditing or building user lists/cards with icon actions, ensure all buttons are wrapped in tooltips that provide explicit `aria-label`s. Always safeguard destructive actions using an `AlertDialog` (or similar confirmation patterns) linked to an intermediate state variable (e.g., `deleteTarget`), confirming user intent before executing the deletion logic.

## 2024-08-30 - Standardize Keyboard Accessibility for Custom Styled Elements
**Learning:** Highly customized UI elements utilizing standard HTML tags, such as glowing circular buttons or flexbox grid containers mimicking buttons (like the `Big Breathe` button or complex CTA buttons on the home screen), frequently omit standard keyboard focus styles because native styling is overridden or disabled. Without these, keyboard users cannot determine which element holds focus.
**Action:** When auditing or implementing highly stylized interactive elements directly using native tags rather than standard UI library components, explicitly apply consistent keyboard focus styles using standard utility classes (`focus-visible:ring-2 focus-visible:outline-none focus-visible:ring-ring focus-visible:ring-offset-2`). Additionally, explicitly assign `aria-label` to visually iconic elements acting as buttons to ensure complete screen reader coverage.
