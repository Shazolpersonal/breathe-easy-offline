## 2024-06-25 - Prevent Accidental Deletion with AlertDialog & Enhance ARIA on Icon-Only Buttons
**Learning:** Icon-only buttons mapping to destructive actions (like delete) on cards/lists frequently lack `aria-label` tags, causing poor screen reader experiences. Simultaneously, the lack of delete confirmations leads to inadvertent data loss.
**Action:** When auditing or building user lists/cards with icon actions, ensure all buttons are wrapped in tooltips that provide explicit `aria-label`s. Always safeguard destructive actions using an `AlertDialog` (or similar confirmation patterns) linked to an intermediate state variable (e.g., `deleteTarget`), confirming user intent before executing the deletion logic.

## 2026-07-02 - Using specific generic locators for components over text
**Learning:** React state navigation means elements appear/disappear based on unmount conditions (like back navigation breaking 'startMiniMode' if not handled). Also, relying on visible text selectors like 'text=Pause' might inadvertently catch other elements on the page rendering the specific locator unreliable, and 'aria-label' mapping doesn't always translate cleanly in deep react node trees when combined with 'role'.
**Action:** When trying to locate hidden or conditionally rendered components like MiniPlayer, aim to use generic DOM element structures in conjunction with their exact accessible strings (e.g. `page.locator('.zen-mode-hide').locator('button[aria-label="Pause"]')`) or test IDs where feasible, and simulate the exact user sequence that triggers the contextual state instead of artificial URL jumping.
